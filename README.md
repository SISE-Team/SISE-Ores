# SISE Ores 0.8.0 — NeoForge 26.1.2

真正注册在 `sise_ores` 命名空间下的统一材料模组；模组来源名称为 **SISE Ores**。

项目使用 [MIT 协议](LICENSE)。模型和纹理引用已安装模组，不打包上游图像资源；第三方模组仍遵循各自协议。

## 当前材料范围

- 192 个审核物品组，注册 176 个 SISE 物品形态，兼容 458 个原有物品 ID；铜锭、铜粒归并到原版物品。包含 158 组普通材料／桶、20 组矿石和 14 组重复装备。
- 同合成表的九件青铜装备统一为 Mekanism Tools；Prefab 的木、石、金、钻石速刃统一为 Aquaculture 对应水产刀，铁速刃和铁水产刀统一为优先级更高的 CakestickLib 凿子。采用优先物品的原生属性与行为，隐藏旧条目，IC2 最后。撤销 15 条旧装备改摆法补丁，原材料数量与产量保持，不新增装备转换配方。比较输入域时包括标签交集，例如石质水产刀的圆石标签与石质速刃的圆石输入。
- 与 SISE Compat 0.5.1 联合统一生产配方：同输入、同工艺阶段按优先模组的每单位原料产出比例对齐；不足整数的路线使用完整批次，例如 3 粗铜 → 4 铜粉。生产修正在 Compat 的 `production.json` 中维护，保留原生机器路线。0.8.0 的装备统一不改动这些生产规则。
- Oritech exp11 的矿脉生成资源采用新版加权对象格式，并包含新增的 other 分组。保留节点、权重、可选依赖和生成参数，仅替换周围已审核矿石身份。
- 新版 Oritech 的 Powah 充能兼容配方和可选铸造配方纳入明确字段的材料统一；保留能耗、铸模、流体量和加载条件。
- 统一顺序为 Mekanism → MekMM → Modern Industrialization → Oritech → EnderIO → LTXI → NeoEcoAE → Ice and Fire → CakestickLib → 其他模组 → IC2CE；IC2 始终最后。Mekanism Generators 归入 Mekanism 系。
- 化学品注册表增加蒸汽、氢、氧、氯、硫酸的 SISE 身份，与 UU 化学品共六组。真实热力锅炉和 JEI 生成配方均使用 SISE 蒸汽；普通蒸汽生产以 1 mB 水 → 1 mB 蒸汽为准，冷凝和 MI 普通蒸汽配方同步对齐。
- UU 固体、UU 液体及 MekMM 的 UU 化学品分别统一到 `sise_ores:uu_matter`；保持各自物品、流体和化学品注册表及原有转换产量，不新增固液互转。
- 18 组流体覆盖 72 个原静止／流动 ID 与 46 个旧桶：UU、蒸汽、重水、氢、氧、氯、氮、甲烷、硫酸、盐酸、杂酚油、原油、柴油、石脑油、生物燃料、乳胶、乙醇、熔融红石。流体配方、传输资源、储罐和桶的内容统一为 SISE 身份，体积、数据组件和原有燃料能量保持。
- 废料与普通硅晶圆统一；九份废料的 IC2 废料盒和 64 份废料加化学品制成的 MekMM 压缩废料盒均归属 SISE，但名称、配方及用途分开。
- 铁、金、铜、锡、铅、青铜、普通钢、银、硅、钛的普通板材，以及碳纤维板、塑料片纳入统一；新增铜、铁、金、钢、钛、木齿轮。本轮补入 18 组、46 个原物品 ID。板材按原来的锻造、轧制、压缩、冲压和磨粉路线加工。
- 新增煤粉、碳粉、钻石粉、绿宝石粉、末影珍珠粉、青金石粉、黑曜石粉、石英粉、硫粉、钠粉、锂粉、普通钚粉、盐、木屑、面粉，以及粗硅、锻铁锭／粒／块、木炭块和九份盐块。
- 13 组小撮粉末按 1/9 单位单独统一；不会与整粉 1:1 等价。IC2CE 的 73 个原物品 ID（含 6 种矿石及 9 件装备）及其专用配方格式已经纳入。碎矿、纯净碎矿、核燃料与同位素保留加工阶段。
- 所有新材料保留优先来源的燃烧时间；储存块复制来源的硬度、声音和采掘属性。煤粉和碳粉、MEK 四份盐块和九份盐储存块、铀粉块和铀锭块分别保留。
- 铁、金、铜的粉使用 SISE 身份；原版锭、粒、块仍保留原版。MI 和暮色森林铜粒的产出统一为原版铜粒。
- 锡、铅、银、镍、铝、铂、钛、钨、铀、青铜、普通钢、琥珀金、锇统一锭、粒、粉和可放置储存块。
- 锡、铅、银、镍、铝、铂、钛、钨、铀、锇的粗矿、粗矿块和矿石方块均归属 SISE Ores。41 个原矿石 ID 在世界生成时归并成 20 个对应宿主岩石的矿石版本；掉落与加工产出继续统一。
- 普通硅与硅锭路线分别注册：硅／硅块，以及硅粉／硅锭／硅粒／硅锭块。两种块的工作台拆分和 MI 解包机输入严格分开；不因共用公共标签而互相转换。
- 外观参考优先级：Mekanism → Mekanism More Machine → Modern Industrialization → 其他模组。模型直接引用已安装模组，不复制其纹理。
- 通过 NeoForge `ModifyRecipeJsonsEvent` 处理实际加载的配方；输入改为明确的等价标签，输出改为 SISE Ores ID。
- Ores 的身份替换保留原配方数据；Compat 随后按来源优先级校准同类生产的产物、数量及副产物。整批加工同步扩大用料与时间／总能耗；单输出槽或概率格式无法承载参考副产物的四条路线按用户选择只对齐主产物比例，保留原生副产物。压块／拆分和不同纯度加工保持单位关系。
- 切石机单向转换：放入一份旧材料，选择一份对应的 SISE Ores 材料。标准物品本身不能再次匹配该转换；不会与工作台块拆锭、锭拆粒配方争抢。
- SISE Compat 0.4.0 保留七条普通粉末的工作台拆分；硫粉拆小撮粉、铀块拆铀-238 用材料加可重复使用的 IC2 锻造锤区分，数量仍为 1:9。七条有来源校验的钢板／齿轮制造输入修正排除生物钢。切石机只承担旧材料迁移等明确的手动转换。
- JEI 浏览器和配方轮换隐藏旧物品、旧流体与六组旧化学品；创造标签页与搜索隐藏旧物品／桶。统一后的材料、流体与化学品只显示 SISE 身份。使用 `@sise_ores` 或 `@SISE` 查找。

## 边界

普通板材与上述重复齿轮按明确白名单统一。致密板（九张普通板）、大型板、弯曲板、掺杂硅板、AE2 印刷硅板和强化碳片保留加工阶段；MI 压缩碳粉板与 IC2／CakestickLib 碳纤维复合板分开。IC2 橡胶薄片是可铺设的方块，MI 橡胶片是合成部件，保留原有行为。杆、线材已扫描，当前公共标签与同名物品没有新增的普通等价组；不同模组的电缆保留电网行为。

流体白名单在 `fluids.json`。Mekanism 的低温液氢／液氧／液氯、同位素、过热／高压蒸汽、奇异物质和不同 XP/mB 的经验流体保留不同阶段和单位。仅共享宽泛标签不足以合并。旧容器中的流体在原生堆栈、模板和传输资源构造时规范化，不批量扫描存档或改写已有区块。IC2 普通蒸汽适配器原来的 10→16 同物质增量路线停用，过热蒸汽路线保留；UU 制造机、复制机、废料和燃料使用原生接口兼容。

## 0.3.0 世界生成

统一身份为 `sise_ores:*_ore`，外观、硬度、采掘等级、声音和矿石掉落规则取同一宿主岩石下优先级最高的来源：Mekanism → Mekanism More Machine → Modern Industrialization → 其他模组。原版矿石仍使用原版身份。

| 金属 | 石头版本外观 | 深板岩版本外观 | 其他宿主 |
|---|---|---|---|
| 锡、铅、铀、锇 | MEK | MEK | — |
| 银 | MEK More Machine | MEK More Machine | — |
| 镍、钨 | MI | MI | — |
| 钛 | MI | LTXI | — |
| 铂 | MI | Oritech | Oritech 末地石版本 |
| 铝 | NeoEcoAE | 原包没有该版本，不虚构 | — |

石头、深板岩、末地石版本分别注册，不能相互转换。原包的生成高度、维度、生物群系、频率、矿脉大小、暴露空气概率和放置规则不变；不同模组原有生成器仍运行，不在这一版重新平衡总矿量。

`OreTargetMixin` 在标准矿石配置的目标构造时替换身份，覆盖 vanilla / MI / Oritech 常规矿脉、MEK 可配置矿脉及其原有补矿目标。`WorldGenOreMixin` 仅处理世界生成区域的方块放置，用于结构与自定义生成器；普通玩家放置和已有区块不受这一入口影响。没有开启任何新的补矿或旧区块改写。

Oritech 的 3 个自定义配置单独替换矿石 ID：资源节点周围岩块、稀有节点周围岩块、铀矿斑。保留资源节点本体、晶簇、油层和所有权重。铝土矿不等于铝矿，晶质铀矿不等于普通铀矿，赛特斯石英充能状态与 LTXI 粗矿簇也保持独立。

普通挖掘产出对应 SISE 粗矿；精准采集得到对应 SISE 矿石；时运保留优先来源的原有算法。例外修复：MEK More Machine 的两种银矿原表无条件掉矿石本身；新的 SISE 银矿采用 MEK 的标准“粗矿／精准采集／时运”规则，仍保留 MEK More Machine 外观与采掘属性。原模组文件不改写。

旧矿石在原世界继续存在，挖掘和加工兼容，库存可通过41 条矿石切石机配方 1:1 转换。

矿石物品列表原料变为多个标签时，使用 NeoForge compound ingredient 保持“任选一种”的原意，避免 26.1 原料列表编解码不支持标签导致 10 条熔炼／高炉配方失效。输入槽列表仍保留原数量与结构。

生物钢、充能赛特斯石英、煤粉/碳粉、专用合金、不同纯度和加工阶段不做自动等价归并。标签重叠不能创建新的等价关系。输出携带显式数据组件或输入为复杂自定义原料时不自动放宽，未处理的引用进入审计报告。

箱子、抽屉、AE 中原有物品会保留；可继续用于兼容配方或手动转换。AE 中已编码并指定旧产出 ID 的样板需要更新为新产出；锁定抽屉、过滤器也需要按新 ID 调整。不要在已经保存新材料的世界中直接移除本模组，否则会缺失这些注册对象。

## 已迁出的兼容修复

0.3.1 已将所有独立兼容修复迁入 **SISE Compat 0.2.0**：NeoEcoAE 的 15 条旧原料格式修复、粉末／钢／硅块冲突处理、MI 手动切石转换保护，以及 RarityCore 同步快照。以下说明记录这些修复的原有语义，实际实现与维护入口统一在 SISE Compat；Ores 保留材料注册、等价标签、身份统一和世界生成。

0.2.0 只处理矿物与材料加工：修复 NeoEcoAE 的 4 条合金／晶体粉碎配方和 3 条晶体修复配方的原料格式。专用合金、晶体及其生长阶段保留原身份、数量和概率。导管、创造物品、电路成品、工具装备、家具、变压器、木炭块的原有问题不归入本轮修复。

EnderIO 使用物品标签表示的材料产出也转换为明确的统一物品；概率和数量保持不变。含义有歧义的公共硅块标签不会自动选产物。

0.1.1 全量审计修复：128 条转换移到切石机；Oritech 的 7 条整粉拆小粉配方改为切石机选择，保留原有 1:9 数量；3 条普通钢压块配方排除生物钢。上述手动选择配方不导入 MI 切割机，以免产生自动加工歧义。

当前装备统一见 [0.8.0 验证记录](docs/verification-0.8.0.md)，生产比例与化学品统一见 [0.7.0](docs/verification-0.7.0.md)，此前 UU／流体统一见 [0.6.0](docs/verification-0.6.0.md)，板材与齿轮见 [0.5.0](docs/verification-0.5.0.md)，全包材料扫描与 IC2CE 统一见 [0.4.0](docs/verification-0.4.0.md)，归并结果见 [0.3.1](docs/verification-0.3.1.md)。此前 [0.3.0 验证](docs/verification-0.3.0.md)与 SISE Compat 0.1.1 联合运行时，实际配方加载错误和工作台冲突均为 0。全包机器循环没有逐一穷举，具体候选与本轮差异见最新验证记录。

NeoEcoAE 的 8 条铝／钨 MEK 加工配方使用旧版 `{count, tag}` 原料格式，现转换为等价的 `{count, ingredient: "#..."}`，保留数量和标签含义。

RarityCore 2601.14.2 的 `RaritySyncPayload` 直接持有可并发修改的稀有度映射。新增材料触发重算时，编码长度和实际条目数可能不一致，导致 `raritycore:rarity_sync` 解码失败。快照修复由 SISE Compat 提供；Ores 不再包含此 Mixin。

## 维护与构建

主分支：`26.1.2`。Python 构建、验证和维护脚本统一保存在本地 `tool/`，该目录及所有 `*.py` 文件均由 Git 忽略，不随仓库提交。独立克隆只包含源码、规则和文档；构建需另行准备本地工具，详见 [构建说明](docs/BUILDING.md)。

- `materials.json` 与 `fluids.json`：审核后的物品、流体和化学品清单；新模组的材料不会因为同标签而被自动纳入。
- `src/main/java/.../RecipeTransform.java` 与 `FluidRecipeTransform.java`：按配方格式识别物品输入／输出及流体／化学品字段；保留数据组件与条件。
- 本地 `tool/build.py`：生成标签、翻译、物品模型引用、方块掉落、转换配方，然后用工作区 JDK 25 编译。只清理本工程 `build/classes` 和 `build/resources`。
- 本地 `tool/test.py`：遍历已安装模组中的实际配方，检查身份替换之外的所有数据保持不变、重复执行幂等、特殊材料排除和无遗漏。
- 本地 `tool/verify.py prepare` / `tool/verify.py launch`：在 `.work/test-sise-equipment-20261017` 中启动完整模组环境，使用离线身份和新建普通地形测试世界；验证注册、标签、物品统一、压缩拆解、跨模组配方、板材及 UU 机器加工、桶与储罐、方块掉落、JEI 来源、显示和重新加载，并回归当前 SISE Compat 修复。
- `EquipmentChecks` 与本地 `tool/equipment_audit.py`：扫描实际装备合成，执行原始及镜像网格，核对全部匹配配方的原生装备产物，检查旧条目隐藏、耐久及附魔保留，并与当前上游版本的升级前导出逐条比较，确保其余配方不变。
- `WorldgenChecks.java`：扫描实际生成的主世界与末地区块，核对已加载世界生成配置，逐项调用 41 种原矿石的真实 OreFeature 与 WorldGenRegion 放置，检查 20 种新矿石的普通挖掘、精准采集、时运、工具等级及特殊矿物边界。证据保存为 `verification/worldgen-report.json`。
- 本地 `tool/audit.py`：审计完整运行导出，比较统一前后配方输入域、机器同输入产出、材料守恒和原有加载失败；生成 JSON 明细及中文报告。
- 矿物原料格式和配方冲突修复由 SISE Compat 的 `rules.json` 与 `materials/RecipeSafety.java` 维护。
- `MaterialLootModifier.java`：战利品计算后归并审核材料，保留时运数量；装备转换保留名称和附魔，耐久采用优先物品的原生语义，普通材料带显式组件时保持原样。原生无耐久的凿子不会被附加旧刀具的耐久属性。
- 正常运行时审计：游戏实例的 `logs/sise-ores-unification.json`。

已准备好本地 `tool/` 的维护环境中，从实例根目录运行：

```powershell
python .work\SISE-Ores\tool\build.py
python .work\SISE-Ores\tool\test.py
python .work\SISE-Ores\tool\verify.py prepare
python .work\SISE-Ores\tool\verify.py launch
python .work\SISE-Ores\tool\audit.py
```

这是针对当前整合包的明确材料白名单。升级模组后应检查审计报告并重新运行验证，不应以字符串替换方式直接扩展到所有材料。
